# スライムのターゲット点群変形・実装プラン

作成日: 2026-10-15

本書は [新ゲームデザイン](SlimeRebootPlan.md) の変形攻撃を具体化する技術計画。ハンマー、剣、飛行機は、**武器メッシュから生成したターゲット点群へ、既存の流体粒子を割り当て、ばねで追従させる方式**で統一する。本書の作成時点では未実装。

## 1. 採用する構成

```text
閉じた武器メッシュ＋部位ラベル
    ↓ 事前サンプリング
表面付近と内部を満たすローカル点群
    ↓ 変形開始時にGPU上で一対一に割り当て
粒子の元インデックス → 目標点インデックス
    ↓ 各サブステップ
目標点を姿勢・質量・変形進行度で動かす
    ↓ ばね＋相対速度の減衰
既存の密度補正・粘性・地形衝突
    ↓
既存の流体表面再構成で描画
```

点群は粒子の「行き先」であり、別の描画用粒子ではない。現在の位置・速度を引き継いだまま変形する。目標座標へ直接テレポートさせない。

## 2. 現行実装と接続上の注意

今回確認した実装を基準とする。以下の数値は現在値で、新方式の確定仕様ではない。

| 現行箇所 | 確認できた状態 | 変更方針 |
| --- | --- | --- |
| `Engine/Renderer.h` | プレイヤー用粒子枠は6,600。`GPUFluidParticle` は64バイト | 初期試作はこの枠内で固定数。目標情報は別バッファにし、既存粒子のレイアウトを維持 |
| `Resources/shaders/FluidSimCS.hlsl` | `OriginalIndices` でソート済み粒子と元スロットを対応付け | 目標割り当ては元スロットをキーに保持。空間ソートで割り当てを変えない |
| 同 `CalcForce` | 外力を積分する処理、通常形状の制御、デコイの目標追従が存在 | デコイ処理は参考にし、武器用の明示的なばね制御を追加 |
| 同 `ApplyDeltaP` | 密度補正後にも通常スライムの領域制御がある | 武器変形中に通常のドームへ押し戻さないよう、制御を切替・補間 |
| 同 `SavePrevious` | コア移動の転送、非アクティブ粒子の復元がある | 目標速度による追従と同じ移動を二重適用しない。変形中の粒子集合を固定 |
| `Engine/Renderer.cpp` | サブステップ内で外力積分→密度の位置補正→速度更新を実行 | 既存の順序を維持し、外力段階へ点群追従を接続 |
| `tests/SlimeFluidTests.inl` | 製品HLSLを実行するGPU試験がある | 新しいSRV・UAV・定数のバインドを試験側にも反映 |

`Particle.pad` は既存用途があるため、未使用と見なして目標IDを詰めない。また、既存の `coreMode` の数値へ武器種類を追加し続けず、独立した変形状態とデータを設ける。

既存の位置補正を用いる流体密度ソルバーは維持する。PBFは粒子の密度を位置制約で扱う手法であり、本案ではその外力段階へ目標追従を追加する。追加した強いばねまで自動的に安定する保証はないため、時間刻みと係数の検証を別途行う。[Position Based Fluids 原論文](https://mmacklin.com/pbf_sig_preprint.pdf)

## 3. ターゲット点群を作る

### 3.1 形状と部位

最初は閉じたハンマーメッシュ一つを用意する。ヘッド、柄、根元をラベルで区別する。初期形状は単純な箱・柱を結合して作ってよいが、重複領域を除いた一つの閉じた体積として扱う。

剣は刃・柄・根元、飛行機は胴体・左右の翼・尾翼へ同じ仕組みを広げる。部位ごとに別々の粒子システムは作らない。

### 3.2 サンプリング

1. メッシュの座標系、原点、正面、体積を揃え、穴・裏返り・内部判定の失敗を検出する。
2. 内外判定ができる体積表現を作り、内部から境界付近まで、おおむね均一な間隔で候補点を生成する。
3. 境界付近には表面に沿う点を配置する。ただし内部点と重複する密集した表皮を追加せず、最小間隔を保つ。
4. 最終的に有効粒子数Nと同じN点へ調整・緩和し、部位IDとともに保存する。乱数シードは固定する。
5. 各点の近傍間隔、体積内の偏り、部位をつなぐ厚みを検査する。

メッシュの既存頂点をそのまま使うと、ポリゴン分割の細かい場所だけ密集するため、三角形面積と体積を基準に再サンプリングする。形の内部を満たし、流体の密度補正と大きく競合しない分布にする。

### 3.3 密度・厚み・体積

- 通常形状と武器形状の基準体積を揃える。変形だけで質量や密度の基準値を増やさない。
- ハンマーのヘッドに多くの粒子が入るのは、その部分の体積が大きいためとする。柄を不自然に疎にして見かけだけヘッドを太くしない。
- 柄、刃、翼には、粒子間隔と表面再構成グリッドで連続した液面が出る最小厚みを設ける。必要なら元メッシュを太くする。
- 表面の平滑化で刃が丸くなることを想定し、鋼のような極薄形状ではなく、厚みのあるスライムの剣を目指す。
- 実際に復元される流体表面の体積とシルエットも測り、点群の体積が一致しただけで完成とはしない。

## 4. 粒子と目標点を割り当てる

### 採用案: 変形開始時の空間順序による一対一対応

GPU上の現在位置を利用しつつ、毎フレームの全粒子読み戻しや全組合せの探索を避ける。

1. 変形する個体の有効な元スロット一覧と、その時点の位置をGPU上でスナップショットする。
2. 現在位置を個体ローカル座標へ変換し、通常形状と武器形状を含む共通の量子化領域で空間キー（Mortonキー）を作る。
3. 粒子側を `(空間キー, 元スロット)`、目標側を `(空間キー, 目標ID)` で並べ、同じ順位同士を対応付ける。
4. `TargetMap[元スロット] = 目標ID` を書き、一回の変形が終わるまで保持する。同時に、開始位置をローカル座標で保持する。

同一キーでもIDで順序を確定する。無効スロットとソート用の余白は除外し、N粒子とN目標の一対一対応を保証する。点群と割り当ては作業用バッファで作り、完了してからまとめて有効化する。

現在のCS 5.0構成で動くソートを選ぶ。初期候補は最大6,600点を8,192要素へ詰めたbitonic sortだが、必要パス数と開始時の負荷を測り、radix sort等との比較で決める。割り当て準備中は通常形状を維持し、必要なら準備を複数フレームへ分ける。

この方法は移動距離の最小解ではなく、近さを保つための近似。デバッグでは移動線、最大移動距離、交差や中央への集中を可視化する。大きな交差が残る場合は近傍のペア交換で移動距離を改善する。毎フレーム最近傍へ再割り当てする方式にはしない。

### IDの寿命

空間ソートの順位は毎サブステップ変わる。`OriginalIndices` を経由して元スロットへアクセスし、ソート順位を粒子IDとして使わない。

元スロットはプール再利用で別個体の粒子になり得るため、所有個体と世代番号も検証する。変形終了・個体破棄・粒子集合の変更で割り当てを無効にし、過去の目標が別粒子へ適用されるのを防ぐ。

## 5. ばね追従と変形の進行

### 5.1 動く目標を作る

各目標を、個体ローカルの開始位置から武器点群の位置へ、滑らかな進行曲線で補間する。これを個体の位置・姿勢・質量スケールと攻撃モーションでワールド座標へ変換する。

```text
localGoal = lerp(startLocal, weaponPoint, morphBlend)
worldGoal = bodyTransform × attackTransform × localGoal
```

初期版は一つの攻撃ルートで全体を動かす。部位ごとの遅れは、柄が先に伸びてヘッドが後から膨らむなどの演出として追加する。境界を滑らかに補間し、部位の切れ目を作らない。

単純な位置補間だけでは中間形状の体積保存は保証されない。変形途中の密集・空洞も検査し、問題が出る場合は「収縮姿勢→柄の伸長→ヘッド形成」の中間点群を追加する。密度補正に無理に押し返させるだけで解決しない。

### 5.2 Spring Force

制御は、粒子位置x・粒子速度v・目標位置q・目標速度uに対し、次の加速度を基本とする。

```text
aFollow = omega² × (q - x) - 2 × zeta × omega × (v - u)
```

`omega` は追従の速さ、`zeta` は減衰。これは単位質量あたりの制御式とし、既存の密度で除算する外力処理へ接続する際に密度を二重に掛けたり除いたりしない。

目標速度uは、平行移動だけでなく回転・形状補間による動きも含め、サブステップ前後の目標位置から計算する。動く武器を静止目標向けの減衰で止めない。

部位別の追従強度を持たせ、ヘッドは形を保ち、柄・根元は少し遅れて伸びる表現へ調整する。配合の弾力・粘りは、追従強度、減衰、復帰時間へ対応させる。

強いばねを現行の積分へ足すだけで安定するとは扱わない。試作ではばね項を陰的に扱う積分を候補とし、重力等の外力を含めて一回だけ積分する。追従加速度・粒子移動量・目標速度に上限を設け、既存の速度上限に常時張り付くモーションを避ける。

### 5.3 通常形状との切替

- 変形の進行に応じ、通常形状の制御を弱め、点群への追従を強める。
- 外力側の形状制御と、密度補正後のドーム拘束を両方見直す。どちらかだけ切り替えない。
- 密度補正、粘性、表面張力、床・壁との衝突は継続する。最終位置では衝突を優先する。
- ばね追従の移動分と既存コア転送の移動分を二重計上しない。点群変形中の輸送方針を一つに統一する。
- ポーズとヒットストップでは、粒子だけでなく目標の進行・攻撃ルートも同じ時間軸で止める。

### 5.4 取り込みの「両手で包む」動作への適用

武器形状と同じ点群追従を、取り込みの連続形状にも使用する。取り込み方向を個体の正面軸とし、体の前側全体が左右へ広がり、厚みのある二つの縁で対象を包み込む形にする。

本体の開始トリガーは取り込みボタンの押下で確定。範囲内の対象を選択して予約し、方向合わせ・点群割り当て・開く動作へ進む。接近・接触では開始せず、一回の押下で一回実行する。子は自動戦闘AIから同じ取り込み状態を開始する構成案を継続する。

- ローカル形状を「後部・支持部」「前側左」「前側右」「中央のくぼみ」へ滑らかな部位ウェイトで分ける。前側を開いても後部が支えとして残るよう、粒子の体積を配分する。
- 開く・包む・閉じるの各点群は同じN点と点IDを共有する。動作開始時に一度割り当て、途中で左右の粒子が入れ替わる再割り当ては行わない。左右の部位をまたぐ割り当てを制限し、境界の移動を滑らかにする。
- 点群の段階は `通常 → 左右へ開く → 側面から奥へ包む → 中央へ閉じる → 通常`。隣り合う段階をばねの目標として補間し、閉じる途中で中央が過密にならないよう点間隔と体積を検査する。
- 最大開き幅・奥行きは個体の大きさから決め、その範囲内で対象の包囲形状に合わせる。ターゲットが大きすぎる場合は点群を無制限に拡大せず、ゲーム側の必要質量判定で開始を止める。
- 開く段階までは対象方向に追従し、包む・閉じる段階では旋回速度を制限する。前方向の水平成分で正面を決め、高さの違いは前側の形状で吸収する。同一位置など方向が定まらないときは直前の正面を保持する。
- 床・壁は通常どおり衝突対象とする。取り込み対象については、左右で包む間は粒子用の簡易障害物として扱い、取り込み成立後に体内へ沈める演出へ切り替える。既存の通常障害物と同じ不変の衝突物として残し、閉じられなくなることを避ける。
- CPU側にも同じ正面・開き幅・奥行き・進行度から包み込み範囲を作る。範囲内、質量条件、対象の予約、閉じる段階への到達を確認し、形成状態の診断と合わせて一回だけ取り込みを成立させる。
- 成立前に対象が逃げた場合、姿勢が作れない場合、被弾等で中断された場合は予約を解放して復元する。成立後は同じ対象を再取得しない。粒子集合の更新を伴う成長は復元後に適用する。

試作は静止物一つで開始し、正面・側面・上面から、ガバッと開くシルエットと左右が奥へ回り込む様子を確認する。次に個体サイズの違い、動く対象、壁際、中断、子スライムへ広げる。取り込み音の山は、対象が包まれて閉じる時点に合わせる。

## 6. ハンマー攻撃の状態と判定

```text
通常 → 割り当て準備 → 形状形成 → 振り上げ → 振り下ろし
     → 命中・潰れ → 復元 → 通常
```

最初の調整用の時間案は、形状形成0.3〜0.5秒、振り下ろし0.2〜0.3秒、復元0.4〜0.7秒。割り当て準備時間は別途計測する。確定の操作仕様ではなく、見た目と応答の比較に使う初期値とする。

- 形状形成中は移動・旋回を抑え、ヘッドができる様子を見せる。
- 振り下ろしでは目標点群の攻撃ルートを動かし、粒子が追従して叩きつける。
- CPU側は同じ攻撃ルートからヘッドの簡易形状を作り、前フレームからの掃引で命中を判定する。一攻撃一対象への重複命中を防ぐ。
- 形状形成の終了時に、GPU上で目標誤差・有効粒子数を集計する。少量の結果を非同期で確認し、十分に形成されるまで攻撃判定を有効にしない。全粒子読み戻しや `WaitGPU` は不要な構成にする。
- 形成の遅延や壁への押し付けが続けば、期限を設けて復元へ移る。GPU結果待ちでゲーム進行を無期限に止めない。
- 地形への掃引で目標ルートを止め、壁の向こうへヘッドだけ進めない。見た目の粒子には衝突応答を残す。
- 命中時は短いヒットストップと、体積を補償した一時的なヘッドの潰れを目標へ加える。復元はばねで行う。

ダメージ量はゲーム側の質量・攻撃データから決定する。物理粒子の接触数や瞬間的なばね力を直接ダメージへ変換しない。命中音は実際の命中イベントと同期させ、形成・伸長音は状態遷移と同期させる。

### 通常形状への復帰

復元開始時の現在位置を引き継ぎ、同数の通常形状用点群へ滑らかに追従させる。必要なら復帰開始時に一回だけ再割り当てし、通常のドーム制御へ徐々に戻す。

被弾中断、攻撃空振り、地形への衝突でも同じ復元経路を使う。落下復帰等の大きな位置変更では、目標速度をリセットし、表面再構成の履歴も必要範囲で無効化して残像を防ぐ。

## 7. 固定粒子数と成長・分裂を両立する

**固定する単位は「一回の変形中の有効粒子集合」。** 全ゲームを通して全個体を6,600粒子に固定する意味ではない。

- 最初の試作は一個体、基準質量、有効粒子数固定。武器点群と粒子数を一致させる。
- 拡張時は個体に粒子スロットの集合を割り当て、有効数Nに対応する点群を用意する。最大プール容量と一個体の有効数を区別する。
- 点群は必要なNで生成してキャッシュする。大きい点群の先頭N点を使う方式は、部位欠落や密度偏りが出るため避ける。
- 成長時の体積は質量に比例させ、同じ形状なら寸法は質量比の立方根で変える。Nの変更とは別に、粒子間隔と目標密度の整合を取る。
- 変形中は、その個体の吸収・分裂・合体による粒子集合変更を保留する。復元後に適用して必要な点群・割り当てを更新する。
- 子スライムや水・飛沫のスロットは割り当て対象に含めない。最初は本体のみ武器変形する。

ステージの出発・リトライでは基準質量と粒子構成へ戻し、変形状態・対象予約・目標割り当てを初期化する。配合・素材の解放はセーブ対象とし、成長した大きさやGPU上の変形途中の状態は持ち越さない。

## 8. GPUデータとリソース管理

| データ案 | 内容・更新頻度 |
| --- | --- |
| `ShapePoints` | ローカル目標位置、部位ID。形状・Nごとにロード時またはキャッシュ生成時に準備 |
| `TargetMap` | 元スロットから目標IDへの対応。変形開始・復帰時のみ更新 |
| `MorphStartLocal` | 変形開始時のローカル位置。割り当て時にスナップショット |
| `ParticleOwners` | 所有個体・世代。有効スロットの再利用を検証 |
| `MorphBodyState` | 個体姿勢、前姿勢、質量スケール、変形進行度、部位別係数 |
| `SortScratch` | 割り当て準備用のキーとID。既存の流体近傍ソートとは別管理 |
| `MorphStats` | 平均・最大目標誤差、有効数、不正値。診断と形成完了判定用 |

名称は提案。最終的な構造と配置は実装時に合わせる。GPU粒子の位置を毎フレームCPUへ送り返して割り当てる構成にはしない。

点群は常駐SRV、割り当ては作成時UAV・追従時SRVを候補とする。CSルートシグネチャ、ディスクリプター、バッファの状態遷移、書き込み後のバリアをまとめて追加する。フレームごとの定数と動的領域はフェンスで保護し、CPUとGPUが同じ領域を同時に書き換えない。

空間ソート処理は元粒子を書き換えず、作業用バッファへキーを作る。水・デコイ・飛沫に変形データが漏れないよう、未割り当てIDと所有個体で分岐する。

## 9. 実装順と完了条件

| 順序 | 作業 | 完了条件 |
| --- | --- | --- |
| 1 | ハンマーメッシュ、点群生成、部位色のデバッグ描画 | N点、重複なし、内部充填、柄とヘッドの接続、基準体積を確認 |
| 2 | GPU割り当てとデバッグ線 | 全有効粒子が異なる目標を持ち、ソート後も対応が維持される |
| 3 | 静止したハンマーへのばね追従 | 密度補正を有効にしたまま形を保持し、不正値・極端な振動・柄の断裂がない |
| 4 | 形成・振り下ろし・命中・通常復帰 | 接地・壁・空振り・中断で復帰でき、命中判定と見た目が合う |
| 5 | 小・基準・大の質量と子の存在へ対応 | 個体間で粒子を奪わず、吸収・分裂・合体後にも正しく再割り当てできる |
| 6 | 剣、飛行機、配合差、音同期 | 同じ仕組みの形状データと攻撃ルートの追加で実現できる |

最初の評価範囲は順序1〜4の一個体・ハンマー。子AIや調合UIの完成を待たずに技術的な成立と操作感を確認する。

### 検証

- 点群生成: 点数、体積内外、決定性、近傍間隔、部位の接続、低粒子数での細部欠落。
- 割り当て: 目標の重複・未割り当てがゼロ。空間ソート、スロット再利用、個体切替でも別目標へ飛ばない。
- 数値: 静止・並進・回転、複数フレーム刻み、ヒットストップで有限値を維持。移動する座標系でも過剰な減衰や二重輸送がない。
- 形状: 密度誤差と目標誤差の両方を測る。目標誤差は粒子間隔で正規化し、平均・95パーセンタイル・最大値を記録する。
- 画像: 正面・側面・上面で、柄、ヘッド、刃、翼が流体表面として連続することを確認。特に中間形状と復帰を撮る。
- 戦闘: 形成未完了の攻撃、壁越し命中、同一対象への重複命中がない。中断後も通常移動へ復帰する。
- 負荷: 変形開始時の割り当て、追従追加分、既存密度ソルバー、表面再構成を別々に計測する。開始時の一時的な負荷も含め60fpsの予算へ収める。
- 既存機能: 製品HLSLのGPU試験を拡張し、通常スライム・水・デコイに追加バッファの影響がないことを確認する。

数値の閾値は静止ハンマーの測定から決める。対応が一対一でも、途中の軌道交差・薄い部分の消失・密度との競合は残り得るため、点群・割り当て・追従係数を分けて調整する。
