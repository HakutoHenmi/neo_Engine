# カプセル化のリファクタリング

授業資料の「内部データの公開」「グローバル変数」「friend」「内部構造の返却」を基準に整理した。

- `GameScene` のレジストリ取得は読み取り専用。コンポーネント編集は `SceneComponents` に限定し、全消去・生成・破棄・シグナル接続の変更は公開しない。生成・破棄・全消去はシーンの専用メソッドを使う。
- 選択操作は `SelectEntity` / `ClearSelection` に集約し、主選択と選択集合を同期する。エンティティ破棄時も選択状態を更新する。
- `GameContext` 全体を外部に公開せず、エディターの座標設定は `SetEditorViewport` に集約する。スクリプトは必要なCamera・Rendererのサービスだけを取得する。
- ギズモのモード・ドラッグ状態・軸はEditorUI内のprivateなクラスで管理する。シーン描画は読み取り用APIを使う。シーン保存先もprivateにする。
- 描画設定は読み取り専用にし、変更をRendererの適用・切り替えメソッドに集約する。保存設定の既存の数値範囲と機能の利用可否判定を維持する。
- 体力・最大体力・スタミナ・最大スタミナ・死亡フラグ、およびコンボ・残り時間・時間倍率をprivateにする。回復・ダメージ・体力消費・コンボ更新は専用メソッドを使う。
- EditorUIの広範なfriend権限を削除する。旧ECSのSystem所属集合はprivateにし、集合そのものの変更を許さない。

ECSの位置・描画情報などのデータ構造は維持する。ゲームの計算式、更新順序、死亡フラグを更新するタイミング、JSONの項目名、通常の操作と設定値は変更しない。体力の初期化・復元用APIは既存の保存値や9999のデコイ体力をそのまま扱う。

検証は `tests/Run-EncapsulationTests.ps1` と既存の `tests/Run-ChronoTests.ps1` で実行できる。追加テストは公開APIの制約と従来の体力・コンボ計算を確認する。
