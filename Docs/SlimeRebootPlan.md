# スライム新企画・移行プラン

作成日: 2026-10-15

本書はゲームデザイン刷新の提案書。現行の `GameDesign.md` と実装を確認して作成した。実装済みの仕様書ではなく、新仕様の判断と試作順をまとめる。既存コードの変更・削除はこの作業では行わない。

## 確定した方針

ユーザー確認済み（2026-10-15）。以下の三点を実装の前提とする。

| 項目 | 確定仕様 |
| --- | --- |
| 操作と戦闘 | 本体をプレイヤーが操作し、分裂した子スライムが自動戦闘する |
| 本体の取り込み開始 | ボタンを押して開始する |
| 保存と成長 | 配合・素材の解放は保存し、大きさはステージごとに出発時の基準へ戻す |

## 1. ゲームの核

**「自分で混ぜて作ったスライムが、ぷちっと分裂して戦い、敵や物を取り込んで育ち、巨大な形に変わって暴れる。」**

ジャンル案: スライム調合・成長アクション。

遊びの中心は、スライムの素材感、分裂する気持ちよさ、吸収による見た目の成長、自作の配合による違い。線・囲い・図形認識による攻撃は終了する。ローグライトのラン内カード選択、ランダム強化、引き直し、タグシナジーも今回の遊びから外す。

**本体をプレイヤーが直接操作し、分裂した子スライムが自動戦闘する方式で確定。** 本体は移動・ジャンプ・踏みつけ・取り込み・変形攻撃を操作する。子は追従・索敵・基本攻撃を自動で行い、プレイヤーは分裂・集合を指示する。

## 2. 1プレイの流れ

調合 → 試しに触る → 固定ステージへ出発 → 小さな物を吸収 → 分裂して自動戦闘 → 集合して大きな敵を倒す → 素材・レシピを持ち帰る → 配合を変えて再挑戦。

初回体験の目標は5〜8分。小さな一体から始め、終盤には序盤で吸収できなかった物を取り込めるようになる。

例:

1. ぷるぷるしたスライムを作り、試し場で引っ張る・ジャンプする。
2. フィールドの小さな木片を取り込む。体内で一瞬透け、体がひと回り膨らむ。
3. 子スライムを一体分ける。「伸びる → 首が細くなる → ぷちっと切れる → 着地」の音と変形を楽しむ。
4. 子が近くの小型敵に体当たり。本体は別の物を吸収し、必要なら踏みつけで助ける。
5. 全員を戻して質量を集め、ハンマー形態で装甲を砕く。
6. 弱った敵を包んで吸収し、巨大化。出口を塞ぐ障害物を壊してクリアする。

## 3. 本体・分裂・合体

### 本体の基本アクション

| アクション | 操作と挙動 | 役割 |
| --- | --- | --- |
| 移動・体当たり | 移動して一定以上の速度で接触すると攻撃 | 自然な移動が戦闘につながる。接触し続けるだけの連続命中は防ぐ |
| ジャンプ | 地上でジャンプ入力 | 移動、回避、高い位置の物への接近 |
| 踏みつけ | 空中でもう一度ジャンプ入力すると急降下 | 着地時に潰れ、周囲を押し出す。質量が大きいほど重い打撃 |
| 吸収 | 取り込みボタンを押すと、範囲内の吸収可能な対象へ正面を向けて開始 | 体の前側を左右にガバッと広げ、両手のように対象を包んで閉じる → 飲み込む → 体が膨らむ。成立前に対象が範囲外へ離れると中断 |
| 分裂 | 分裂入力で本体から一体切り離す | 手数と探索範囲を増やす |
| 集合・合体 | 集合入力で子を呼び戻し、接触すると合体 | 大きな対象の吸収、重い変形攻撃への準備 |
| 変形攻撃 | 選択済みの形へ変形して攻撃し、通常形状へ戻る | スライムそのものが武器になる見せ場 |

キーボード案: WASDで移動、マウスでカメラ、Spaceでジャンプ／空中踏みつけ、Fで取り込み、Eで分裂、Rで集合、左クリックで変形攻撃。取り込みのボタン開始は確定し、Fへの割り当ては試作用の案とする。試作では変形一種類に固定し、複数形態が成立してから切替操作を追加する。ゲームパッドにも同じ行動単位で割り当てる。

### 分裂のルール

- 分裂は自分の質量を子に渡す操作。新しい質量は生成しない。
- 初期例: 合計100の本体から20を分けると、本体80・子20。最低本体質量と最低子質量を設け、作れないときは入力前に示す。
- 最初の試作は子一体。次の段階で最大三体まで増やす。子がさらに分裂する機能は後回し。
- 子は親の配合・色・素材感を継承する。個別装備・個別育成は初期範囲に含めない。
- 本体が小さくなれば本体だけで吸収できる物も小さくなる。分散して手数を増やすか、集まって大きさを使うかを選ぶ。
- 子が取り込んだ分は子の質量になる。合体すれば本体へ戻る。HUDには本体質量と仲間を含む合計量を分けて示す。
- 合体は帰還・接触で成立し、入力直後に遠方から質量だけを戻さない。経路が詰まった場合の復帰処理は用意する。

### 自動戦闘AI

状態は「追従 → 索敵 → 接近 → 予備動作 → 体当たり／ジャンプ踏みつけ → 回復動作 → 吸収／再索敵」。集合指示は戦闘より優先する。

吸収できる弱った敵、親の近くの脅威、近い攻撃可能な敵の順に狙う。追跡距離に上限を設け、親から離れすぎたら帰還する。子同士の標的予約と短い標的保持時間で、一体への過剰集中や左右往復を抑える。

個別の移動指示は不要。まずは分裂と集合だけで狙った遊びが成立するか確認する。

子の取り込みは既存のAI案を継続し、条件を満たした対象へAIが取り込み行動を開始する。本体の手動入力と子の行動判断は、同じ取り込み状態へ入る別の開始経路として扱う。

### 質量と耐久を分ける

現行実装では質量とHPが結びついている。新仕様では、質量は大きさ・吸収能力・攻撃特性に、耐久は体を保つ「まとまり」に使う。

- 分裂・合体で耐久が回復したり増殖したりしないよう、現在耐久と最大耐久も質量比で配分・合算する。
- 被弾は耐久を減らし、初期試作では質量を直接減らさない。成長が被弾のたびに巻き戻るストレスを避ける。
- 本体の耐久がゼロでステージ失敗。子の耐久がゼロなら戦えない塊になり、集合で回収できる。回収後も減った耐久を維持する。
- 初期試作では吸収は質量成長のみ。耐久回復は配置した回復ポイントで行い、吸収と回復の無限循環を作らない。
- 分裂中の総合火力は大きな一体と同程度を基準にする。頭数だけで火力が倍増しないよう、威力と攻撃間隔を質量から調整する。

## 4. 取り込んで成長する

吸収の可否は、**その場で吸収する個体の質量**と、対象に設定した必要質量で判定する。見た目の大きさも対応させ、子を含む遠方の合計量で本体が吸収できる扱いにはしない。

| 対象 | 吸収条件 | 体験 |
| --- | --- | --- |
| 小さなオブジェクト | 個体の質量が対象の必要質量以上 | 近づいて取り込みボタンを押し、序盤の成長を作る |
| 生きた小型敵 | 必要質量以上、かつ敵が弱っている | 体当たり・踏みつけの後に包み込む |
| 装甲敵 | 装甲を壊し、必要質量と弱体条件を満たす | ハンマーなどの役割を作る |
| 大型敵・ボス | まず部位や破片を吸収し、本体は撃破後に判定 | 最初から丸飲みにせず、戦闘の見せ場を保つ |

弱体条件の初期候補は残りHP30%以下。必要質量、吸収時間、成長量は対象データとして調整する。吸収可能な対象は輪郭・小さな印・吸着反応で示し、大きすぎる対象は不足を示す。色だけに頼らない。

吸収は一対象につき一回だけ成立させ、複数個体が触っても報酬を重複させない。成長量は吸収前に予約し、個体上限・全体上限を超える吸収は開始しない。成長で必要な空間が確保できない場合も開始を保留し、狭所で体が壁に埋まるのを防ぐ。

体の寸法は質量の立方根を基準に変化させる。攻撃で薄く伸びても吸収能力は質量から判定し、剣の長さを「大きさ」として丸飲み判定に使わない。

ステージは有限の敵・吸収物で構成する。総質量上限を設け、上限到達後も残りの戦闘とクリアが可能な配置にする。

### 取り込みアクションの見た目と流れ

**取り込む方向をスライムの正面にし、体の前側が大きく広がって、両手で対象を包み込むようにガバッと取り込む。** 本体と子スライムのどちらも、この共通の動きを使う。

本体は取り込みボタンを押したときだけ開始し、接触や接近だけでは取り込まない。試作用の対象選択は、押した時点で正面付近にいる、距離・大きさ・弱体条件を満たす対象から選ぶ。正面への近さと距離で優先度を付け、決まった対象へ向きを合わせる。

一回の押下で一回の取り込み動作を行う。動作中の連打は新しい取り込みを開始せず、押しっぱなしでも自動で次の対象へ連続実行しない。対象がいない・大きすぎる等の場合は理由を短く示し、通常操作を継続できる。

1. **向く**: 取り込み対象への方向に体の正面を合わせる。カメラの向きではなく、対象への方向が基準になる。
2. **開く**: 前側の体を左右へ分けて幅広く伸ばす。左右の厚みのある縁が手のひらのようになり、中央に対象を迎えるくぼみを作る。後ろ側は地面に残り、伸びる体を支える。
3. **包む**: 左右の縁を対象の側面から奥へ回し、対象を抱え込む。細い二本の腕ではなく、体の前側全体が大きく開くシルエットにする。
4. **閉じて飲み込む**: 左右を中央へ閉じ、対象がスライムに覆われたタイミングで取り込みを成立させる。対象は包まれながら体内へ沈み、外から突然消えない。
5. **戻って膨らむ**: 広がった前側を戻し、取り込んだ分の成長を反映する。表面がぷるっと揺れて通常形状へ戻る。

開き幅・左右へ回り込む距離・縁の厚みは、その個体の現在の大きさを基準にする。大きいスライムほど広く深く包める。小さい対象に合わせた調整は行うが、小さい個体が大きな対象に合わせて際限なく伸びることはない。

対象は開始時に一つ予約する。正面は開く段階まで滑らかに合わせ、包んで閉じる段階では急旋回を抑えて左右が反転しないようにする。成立前に対象が包める範囲から逃げた場合や、壁で回り込めない場合は閉じる動作を中止して通常形状へ戻る。

取り込みの成立は、対象が正面の包み込み範囲にあり、閉じる段階まで到達したときに一回だけ行う。対象を遠方から引き寄せる処理にはせず、スライムが対象へ覆いかぶさる動きと判定を一致させる。成長による粒子集合の更新は復元後に行う。

点群は「通常 → 前側が左右に開く → 対象を包む → 閉じる → 通常」の連続した形を用意し、武器変形と同じ割り当て・ばね追従の仕組みで制御する。吸収アクション中も粒子数と体積を保ち、開いた部分に応じて体の前後の厚みを配分する。詳細は [点群変形の実装プラン](SlimePointCloudMorphPlan.md) の取り込みへの適用を参照。

## 5. 変形して大きく攻撃する

外から武器を持たせるのではなく、体が伸びて形を作り、攻撃後にぷるっと戻る。初期案では本体が変形し、子は基本アクションで戦う。

変形の実装方式は、ユーザー指定の**ターゲット点群への粒子割り当て＋Spring Forceによる追従**を採用する。武器メッシュの表面・内部から同数の目標点を生成し、粒子と目標点の一対一対応を変形中は保持する。詳細な生成・GPU割り当て・既存流体処理との接続・検証順は [点群変形の実装プラン](SlimePointCloudMorphPlan.md) を参照。

| 形 | 動き | 得意な相手 | 制約・見せ方 |
| --- | --- | --- | --- |
| 剣 | 体が薄く長くなり、横へ大きく薙ぐ | 小型の集団、露出した弱点 | 中程度の予備動作。攻撃後に伸びた体が戻る |
| ハンマー | 一度縮み、先端に体を集めて叩きつける | 装甲、硬い物、近い集団 | 遅いが重い。潰れる着地と復元を強調 |
| 飛行機 | 翼と機首を作り、短時間だけ滑空突進する | 離れた敵、短い列状の敵 | 自由飛行は行わず、低空・距離制限・着地までの一動作 |

どの形でも使用できる質量は変形した個体の分だけ。分裂中は本体の変形が小さくなり、合体後は大きくなる。変形で総体積を増やさず、長くなる部分に応じて薄くする。

形ごとに予備動作・攻撃中・復元中を設け、無制限の連打を防ぐ。まずハンマー一種類で形・命中・音の気持ちよさを確かめ、次に剣、最後に飛行機を追加する。

## 6. オリジナルスライムの調合

調合は戦闘前に行い、試し場ですぐに動き・変形・分裂音を確認できるようにする。ゲーム内の架空素材と配合比として扱う。

| 素材のイメージ | 見た目・触感・音 | 性能の方向 |
| --- | --- | --- |
| ノリ系ベース | 透明感と粘り、糸を引く音 | 基準の体を作る |
| 水分 | やわらかく、流れる音 | 伸びやすいが、形の復元が遅い |
| 弾力ジェル | ぷるぷる、弾む音 | ジャンプと踏みつけが得意 |
| 粘着ジェル | ねっとり、剥がれる音 | 吸収が得意だが移動が遅め |
| フォーム | 不透明でふわふわ、細かい泡音 | 軽快だが重い打撃は弱め |

見た目の色・名前・ラメは性能と切り離す。配合は「弾力・粘り・重さ」の三軸へ整理し、移動、吸収時間、復元時間、打撃の得手不得手へつなぐ。素材を増やすだけで全性能が上がる方式にせず、配合比の合計を固定する。

同じ配合から同じ結果ができる。保存・命名・複製・試し場への出し直しを用意し、比較は二つの配合から始める。初期試作では素材三種類、保存枠三つ程度に絞る。全素材の自由混合や現実の化学反応の再現は行わない。

## 7. ASMRをゲーム体験にする

主役は分裂の音。入力と同時に一発鳴らすだけでなく、見た目の変化に合わせて音をつなぐ。

- 分裂: 粘りながら伸びる音 → 細く張る音 → 小さく切れる音 → 子が着地する音。
- 合体: 接触する湿った音 → 体内へ戻る音 → 表面が落ち着く揺れ。
- 吸収: 前側が左右へ伸びる粘りの音 → ガバッと包んで閉じる湿った音 → 中へ沈む音 → 膨らむ音。包み込みの成立と音の山を合わせる。
- 調合: 注ぐ・混ぜる・泡が抜ける・押す・引っ張る。
- 着地と攻撃: 大きさと配合に応じて、重さ、粘り、泡感を変える。

複数の録音・音素材を使い、同じ音の連打感を減らす。近くの本体と、プレイヤーが指示した分裂・合体を優先し、遠い子の攻撃音は抑える。同時発音数と最小発音間隔を制御する。

BGM・戦闘音・スライム音の音量を分ける。試し場ではBGMを小さくし、戦闘中も分裂・合体の瞬間だけ他の音を軽く下げる。専用バスや位置による音量調整は追加実装が必要で、現行オーディオAPIに完成機能がある前提にはしない。

## 8. ローグライトを外した進行

固定ステージを選び、調合したスライムで攻略する構成にする。レベルアップ時の三択・レアリティ抽選・ランダム取得・ラン内ビルドは使わない。

**配合・素材の解放を保存し、ステージで成長した大きさを次へ持ち越さない方針で確定。** ステージへの出発・リトライでは、開始質量と通常形状へ戻し、分裂した子や取り込み中の状態も初期化する。

| データ | 保存・リセット方針 |
| --- | --- |
| 配合、色、名前、保存レシピ | 恒久保存 |
| 素材・形態の解放、ステージクリア | 恒久保存。固定の初回報酬で解放 |
| ステージ内で吸収した質量、子の状態、現在耐久 | 出発時の基準状態へリセット |
| 失敗時の素材・解放状況 | 失わない。初期案では出撃に素材消費なし |

毎回の出発時は同じ開始質量に揃える。永続成長は調合の選択肢と遊べるステージを増やす方向に置き、質量を持ち越して無制限に強くなる構成は初期範囲に含めない。

本編化する場合の段階案は「吸収を学ぶ場所 → 分裂で集団に対処する場所 → 装甲と変形を使う場所」。最初から複数ステージを作らず、一つの試作コースで全ループを確認する。

| `Game/Chrono/DomainRules.h`、`Game/Systems/HomingDomains.inl` | 線・囲い・捕獲・追尾弾の本編呼び出しを終了 |
| `Game/Systems/RogueliteCombat.inl`、`Game/Chrono/RogueliteRules.h`、`Game/UI/RogueliteUI.h` | 本編のカード、経験値、シナジー、付随倍率、戦闘停止処理を外す |
| `Game/Systems/HordeCombat.inl`、既存ボス・敵モデル | 予告や素材は候補。近接・踏みつけ・吸収向けに数、間合い、HP、攻撃周期を再調整 |
| `Engine/Audio.h`、`tests/GenerateSlimeAudio.ps1` | 再生の基礎と素材生成の足場に活用。分裂同期・音の優先度・音量グループは追加 |
| タイトル、HUD、ロード説明、操作案内、結果画面 | 囲い数・弾数・カードの説明を外し、調合・本体質量・仲間・吸収可否へ変更 |

新ルールは、質量管理、吸収判定、子AI、変形状態、配合データを分離して持つ。GPU粒子は見た目を担当し、命中・吸収・成長の正本はCPU側の軽い判定形状に置く。粒子の揺れやGPU読み戻しで吸収の成功が変わらないようにする。

複数個体の接触だけで勝手に合体しないよう、合体可能な状態と対象を明示する。子を増やすときも粒子総予算は共有し、個体数に比例して無条件に粒子数を増やさない。大きな体の表示範囲、子が親から離れた場合の表示品質、粒子の個体間混入は早期に検証する。

現行では自分から遠い上空の敵が多く、1000体撃破後にボスが出る構成なので、この進行は引き継がない。最初は地上敵を中心に少数を配置し、吸収と変形の間合いを読み取れる戦場にする。

旧機能は新しい試作経路から呼ばない状態を先に作り、関連を調べてから不要コードを削除する。`GameDesign.md` には既存の未コミット変更があるため、本提案では上書きしない。新経路の成立後に正式な仕様書へ反映する。

## 10. 実装フェーズと完了条件

| 順序 | 作るもの | この段階で確認すること |
| --- | --- | --- |
| 1. 触感の試作 | 本体一体、移動、ジャンプ、踏みつけ、静止物の吸収と成長 | 小さい体と大きい体で動き・見た目・届く範囲がわかり、接地とカメラが破綻しない |
| 2. 分裂の試作 | 子一体、質量・耐久の配分、追従、基本攻撃、集合、合体、分裂音 | 総量が増減せず、子が敵を攻撃し、呼べば戻る。分裂・合体自体を繰り返したくなる |
| 3. 最小の戦闘コース | 小型敵と装甲敵、敵吸収、ハンマー変形、固定のクリア目標 | 分けて戦う／集まって吸収・重打撃をする、の両方に使い道がある |
| 4. 調合と保存 | 素材三種類、違いのある二配合、試し場、保存・再読込 | 数値を見なくても、同じ操作で弾み方・粘り・音の違いが伝わる |
| 5. 遊べる一周 | 調合→出撃→成長→クリア→帰還、必要UIと音量調整 | 5〜8分の一周が成立し、再挑戦で別配合を試せる |
| 6. 拡張と整理 | 子最大三体、剣、飛行機、既存ボスの適応、旧機能整理 | 追加前後の負荷と視認性を比較し、基本ループの良さを保つ |

**最初の到達点は「本体一体＋子一体＋小型敵＋装甲敵＋吸収物＋ハンマー」の短いコース。** 調合UIを作り込む前に、この構成で分裂と成長が楽しいか判断する。

工数見積もりは、複数コアの流体表示とハンマー変形の技術試作後に行う。現行の流体を一体ずつ完全複製する前提でスケジュールを決めない。

ハンマー変形の技術試作は、点群の可視化 → 一対一の粒子割り当て → 静止形状への追従 → 振り下ろし・衝突・復帰の順に進める。最初は質量と有効粒子数を固定し、成立後に成長・分裂による個体ごとの粒子数へ対応する。

## 11. 受け入れ確認

- 分裂・合体・子の戦闘不能・同時吸収でも、質量や耐久が増殖せず、同じ対象から成長を二重取得しない。
- 分裂後に吸収できなくなった対象が、集合・合体後には吸収可能になり、理由が画面からわかる。
- 子が標的を切り替え続けない。壁・段差で取り残されても、集合操作で復帰できる。
- 体当たりは同じ接触で多段ヒットし続けない。踏みつけと変形にはわかる予備動作と復元がある。
- 成長・ハンマー変形・合体で床や壁に埋まらず、当たり判定と見た目の範囲が大きくずれない。
- 取り込みは対象への方向を正面にして前側が左右に開き、包んで閉じてから成立する。小・中・大の個体で開き幅が対応し、背後や壁越しの対象が消えない。対象の逃走・中断でも通常形状へ戻る。
- 本体は接近・接触だけでは取り込まず、一回の取り込みボタン押下で一回だけ動作する。長押し・連打・対象不在で意図しない取り込みを開始しない。
- 同じ配合の再作成、保存後の再読込、リトライで同じ基準状態を復元できる。
- ステージ移動・リトライで大きさを基準へ戻し、保存した配合・素材の解放は保持する。
- ステージ中にカード選択や囲いの操作案内が出ず、既存の強化倍率・ボス出現条件にも依存しない。
- 分裂・吸収・合体の音を実映像と合わせて確認し、子が増えても音が埋もれたり急に大きくなったりしない。
- 対象PCで一体／子一体／子三体、最大質量、変形、吸収集中時のCPU・GPU時間を測定する。暫定目標は60fps、1フレーム16.7ms以内とし、実測から粒子予算と同時数を決める。

自動テストは質量・耐久の保存、吸収の条件と一回性、保存復元を中心にする。触感・ASMR・戦場の読みやすさは実機の映像・音・プレイで評価する。

## 12. 試作で優先して評価すること

1. 本体の手動アクションと子の自動戦闘が両立し、取り込みボタンで狙った対象を包めるか。
2. 分裂と合体を繰り返すだけでも楽しいか。
3. 分散する場面と、集合して大きさを使う場面が自然に生まれるか。
4. 調合の違いが操作と音に表れ、自分のスライムへの愛着につながるか。

この順で試し、最初のコースが成立してから形態・素材・ステージ数を広げる。
