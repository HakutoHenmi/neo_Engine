# 流体表面の3D再構成

## 今回の変更

### 通常移動・ジャンプの追従修正

- 通常形状（Zスケール2以下）の粒子目標を向きに依存させない。180度反転で粒子が中央を横切る問題を抑制。細長い攻撃形状と液状化の方向制御は維持。
- 空中でも半球の粒子対応を維持し、接地／空中の球への切替を廃止。上面倍率1.35、XZ補償sqrt(2/1.35)とし、Y復元力を強化。通常ジャンプの極端な縦伸びと移動時の扁平化を軽減。
- 通常プレイヤーのばね減衰をコア速度に対する相対速度へ変更し、独立した重力の二重適用を相殺。コア速度はフレーム間移動から計算し、大きなテレポートでは注入しない。水・デコイ・液状化の減衰は変更しない。
- 反転前後の予測位置一致、等速移動／上昇座標系での変形速度一致を回帰テストに追加。静止試験（スケール1.2/0.8/1.2）で幅6.167、中央上端2.526、外周側上端1.579。実際の入力・戦闘を含む操作感の評価は別途必要。

### プレイヤーのドーム形状の追加修正

- プレイヤーを半径1.2の楕円体内へ戻していた旧クランプを通常プレイヤーから除去。接地時の半球目標と競合して縮む問題を修正し、デコイ用の安全処理は維持。
- 初期方向を立方体乱数の正規化から球面上一様な方向へ変更。頂部を含めた粒子配置の偏りを抑え、基準半径を1.72から2.15へ拡大。粒子数は3,000のまま。
- 接地目標から製品の物理処理を300サブステップ（1秒）進める回帰テストを追加。粒子群の幅6.828、中央上端1.987、外周側上端1.368を確認。再構成画像でも凸ドームを確認したが、実ゲームの同一視点・移動や着地を含む見た目の確認とは別。

### GPU選択・最適化・量と遠方表示（2026-09-24）

### 接地形状・水流・LOD境界の追加修正

- 通常プレイヤーの半球目標は上記の追従修正で更新済み。以前の接地時のみ半球化する方式と弱い復元力は置き換えた。液状化の既存処理は維持。
- 水の発生をランダムな密集球から、流量と発生間隔に応じた規則的な流路断面へ変更。発生順の移動距離を考慮し、連続フレーム間の重複を抑制。横方向のランダム初速は除去。流量増加はノズル幅で受け、粒子数は削減しない。
- 実GPUシェーダーの発生テストで80/160粒子の連続2バッチを検証。密度最大96.703/119.333（基準125）、横初速0を確認。これは入口の検証であり、障害物への衝突・複数水源の重なり・長時間の流れの無条件安定を保証しない。
- LOD移行は当初、水平距離11.5〜15.5単位の円形帯、上下境界4単位だった。遠方の吸収係数、Fresnel、粗さ、屈折式を近距離と揃えた。遠方は依然として個々の楕円なので完全に同一の表面にはならない。
- 接地時の上部下降・底部の横広がりをGPU回帰テストに追加。最終的なドームのシルエットと境界の目立ち方は実ゲームで確認が必要。

- 高性能順のDXGIアダプター列挙からD3D12対応ハードウェアを選択。使用GPUをウィンドウタイトルとログに表示。FPS計測は追加していない。
- 接地水膜で不要な共分散・固有ベクトル計算を省略。スプラットを楕円の正確なAABBに限定し、寄与ゼロの加算を省略。
- サブステップ終端のグリッドは速度更新で位置が変わらないため、次サブステップ冒頭で再利用。PBF反復内のグリッド再構築と反復数・時間刻みは維持。
- プレイヤー3,000粒子、初期半径2.15（以前2,000粒子・1.5、直前1.72）。分離・回収も同じ粒子枠定数を使用。
- scene.jsonの水源を40→80個/60Hz基準へ変更。エフェクト枠は3,000〜27,999の25,000個に拡張。有限プールなので満杯時の循環上書きは残る。
- 当初の近距離は32³単位・セル幅0.25の3D再構成。外側の生存粒子は楕円インポスターで描画する。遠方用の距離破棄はしない。

### 表示距離と負荷の調整

- Development実機のゲーム画面で28,000近い粒子枠と10サブステップのとき、GPU流体合計39.71 ms中、粒子シミュレーションが33.19 msを占めた。空間グリッドは1フレームにつき `1 + 4×サブステップ数` 回構築され、10サブステップでは41回になる。CPU側のコマンド記録はシミュレーション0.747 msで、主な負荷はGPU側。
- サブステップの上限刻みを1/300秒から1/180秒へ調整。速度上限30で1ステップ最大移動は約0.167単位となり、0.4単位の近傍セルの半分未満。1/30秒のフレームでは10→6サブステップ、グリッド構築41→25回となる。Development診断シーン（7,400粒子枠、固定1/60秒）ではシミュレーションGPU時間が12.62→7.79 msになった。28,000粒子の実ゲームでの改善率と動きの安定性は再確認が必要。
- 簡易表示への移行開始を中心から46単位、完了を48.5単位へ変更。直前の23単位から開始距離をさらに2倍にした。
- グリッドを176×64×176、セル幅0.56へ変更。水平範囲は98.56×98.56単位、高さは35.84単位。セル総数は直前の128×80×128の約1.51倍。物理粒子の配置と水のシミュレーションには変更を加えない。
- 粒子形状の近傍探索では、半径1.1の範囲に届かないハッシュセルを読み込む前に除外する。検索結果は同じで、粒子あたりのハッシュ参照を減らす。
- セル幅が広がるため近距離の表面解像度は下がる。セル幅0.56、粒子間隔0.4の薄膜をGPU回帰テストで確認したが、ゲーム内の見た目は別途確認する。
- 遠方は同じ楕円形状を使うが、密度場の連続等値面ではない。個々の輪郭・重なりが見える場合があり、屈折も簡略化。これはユーザー了承済みの遠方品質とのトレードオフ。近距離外周の切替見え方は実ゲームで要確認。
- 水の5秒寿命、画面外クリップ、粒子プール上限は別の仕組みとして残す。「距離によって見えなくなる問題」の対策であり、無期限・無制限の液体保持ではない。

GPU流体の通常描画を、粒子球の深度を2Dで平滑化する経路から、次の経路に置き換えた。

```
既存の粒子プール・発生・回収・プレイヤー操作
  → 外力による予測 / PBF密度補正 / XSPH粘性
  → 材質ごとの近傍共分散・PCA
  → 異方性カーネルを3Dグリッドへ加算
  → 3軸の軽い平滑化 / 速度による履歴の逆移流
  → 等値面レイマーチ（深度・3D勾配法線・厚み）
  → 吸収・Fresnel反射・画面空間屈折
  → 孤立した水粒子を小さな飛沫として描画
```

FLIPへ移行したわけではない。シミュレーションはPBF、描画は粒子から再構成した密度場の等値面である。粒子の運動と表面再構成を分離しているため、楕円カーネルや描画の平滑化は物理位置を変更しない。

### 主な実装箇所

- `Engine/FluidVolume.cpp`: リソース、パイプライン、各パスの接続。
- `Resources/shaders/FluidVolumeCS.hlsl`: PCA、スプラット、平滑化、履歴補正、空領域スキップ用グリッド。
- `Resources/shaders/FluidRaymarch.hlsl`: レイマーチ、合成、小さな飛沫。
- `Resources/shaders/FluidSimCS.hlsl`: PBF、粘性、既存操作・衝突との接続。
- `Engine/Renderer.cpp`: 実時間刻み、サブステップ、Jacobi用バッファとバリア、旧描画との排他。

## 設定と設計上の注意

| 項目 | 現在値 / 挙動 |
| --- | --- |
| 密度グリッド | 128×80×128、セル幅0.4、51.2×32×51.2ワールド単位 |
| 配置 | プレイヤー付近、セル境界へスナップ。高さ範囲は中心のY−8〜Y＋24 |
| 等値面 | 正規化密度0.25。旧セル幅0.25での水膜回帰結果は新しいセル幅へそのまま適用できない |
| 材質 | R=プレイヤー・分離スライム、G=デコイ、B=水。密度を混ぜない |
| 異方性 | 半径1.1の同材質近傍からPCA。軸比を最大4:1、軸長をセル解像度と上限1.1で制限 |
| 再構成体積 | `1 / clamp(実測密度, 自己密度24.4794, 材質の基準密度)`。基準密度だけで小さく表示していた問題を修正 |
| 疎な水 | 床・直近のAABB上面接触は扁平な水膜。空中かつ半径1.1に同材質近傍がない粒子のみ半径0.045の飛沫 |
| 解像度補償 | 接地した薄膜には粒子間隔に応じた1セル相当の最小再構成体積を与える。物理質量は変更しないが、描画上の厚みは増える |
| 平滑化 | 各軸 `[0.125, 0.75, 0.125]`。形状形成の主役はPCAカーネル |
| 履歴 | 速度で逆移流、前回原点を考慮。近傍範囲へクランプ、最大20%混合。現フレームに支持がなければ履歴を残さない |
| レイ | ピクセル単位で正規化。シーン深度をレイ距離へ換算し、4³ブロックの保守的最大密度で空領域をスキップ |
| 物理カーネル | 半径0.4、質量1、水の基準密度125、スライム275 |
| PBF | 各サブステップ3反復。各反復で近傍グリッドを再構築。自由表面では圧縮側のみを補正 |
| 時間刻み | TimeManagerの実時間。速度上限30に対し最大1/120秒のサブステップ（最大移動0.25単位、近傍半径0.4未満）。1フレームの計算時間は最大1/30秒。ヒットストップに対応 |
| 過負荷時 | 1フレーム最大1/30秒ぶんを計算。低FPS時は進行が遅くなる設計で、無制限の追いつき計算はしない |
| 粘性 | 水2、スライム40を `1−exp(−係数×dt)` でXSPH混合へ変換 |
| 発生量 | エミッターの保存値を60 Hz基準の個数として実時間へ換算。端数を持ち越し、計算時間と同じ1/30秒上限を適用 |
| 水の寿命 | 最初の接地から5秒。床とAABBの両方に接触しても年齢は1ステップにつき1回だけ進む |

近傍の「80個で打ち切り」を除去し、ハッシュ衝突では実セル座標も確認する。近傍を読む計算と位置・速度の公開は別パスに分けた。前フレームを処理中のGPUと競合しないよう、衝突AABBの転送にもフレームごとのアップロード領域を使う。

通常のGPU流体では旧2D経路を呼ばない。旧経路はCPU液体と3Dリソース初期化失敗時のフォールバック用に残してある。影は従来の近似粒子シャドウのままであり、今回の等値面そのものの影ではない。

## 確認方法

エディターの **Tools → Fluid diagnostics** で切替できる。

Development構成では **Tools → Fluid Profiler** を開くと、完了済みフレームのGPU時間を粒子シミュレーション、形状生成、密度スプラット、平滑化、レイマーチ、遠方表示、影に分けて表示する。ゲーム描画全体のGPU時間と流体以外の差分も表示する（エディターUIとPresentは含まない）。各区間の直近値・120サンプル平均・最大値・合計履歴に加え、CPUのシミュレーション／ボリュームコマンド記録時間、粒子枠数、サブステップ数、空間グリッド再構築回数、FPSも表示する。GPU結果はフェンスで完了したフレームの読み戻しなので、現在フレームより遅れる。画面を閉じるかPause captureを選ぶと新たなタイムスタンプ記録を止める。

1. Material: 通常材質。
2. Material phases: プレイヤー緑、デコイ黄、水青。
3. 3D normals: 球ごとの法線ではなく連続面の法線を確認。
4. Thickness: 各材質の通過距離。
5. Domain / ray steps: 計算領域とレイの処理量。ステップ上限到達はマゼンタ。

### 自動テスト

リポジトリ直下で実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Run-FluidTests.ps1
```

Visual Studio C++ツールでヘッドレステストをビルドし、製品と同じHLSLをD3D11 WARP上で実行する。ゲーム本体のD3D12バインド確認とは別の数値・描画テスト。

- 圧縮粒子群の平均 `max(密度/基準密度−1, 0)` は、3反復で **1.7995 → 0.2631**。6反復で確認した0.0003とは条件が異なる。完全な非圧縮性を保証する数字ではない。
- 孤立粒子の自己密度24.4794、圧縮側lambda=0、有限の速度と上限30を検証。
- 材質分離、孤立水粒子の飛沫分類、平滑化前後の密度総和誤差0.1%未満を検証。
- 旧セル幅0.25では、1粒子層の薄い面をセル内で4段階ずらして検証。さらに粒子間隔0.4・0.6の疎な床面を追加し、面中央の各列の最大密度の最小値0.334以上で等値面0.25を上回った。セル幅0.4・間隔0.4の最小列ピークは0.857、今回のセル幅0.56・間隔0.4では0.358で、いずれも等値面0.25を上回った。
- 密度64まで広がったスライムの外周が残ること、床面が飛沫へ分類されないこと、床とAABB同時接触時の寿命更新、5秒の寿命を検証。
- 30 / 60 / 120 FPSの1秒分の発生数が同じ2400個（丸め誤差1個以内）になることを検証。
- 空領域スキップの保守性、レイマーチの有限深度、不透明な前景による遮蔽、消滅後の履歴ゼロを検証。
- `tests/out/` に材質・法線・厚みの合成テスト画像を出力する。実ゲームのスクリーンショットではない。

現状、テスト一式は既存の `player crown is pushed sideways or collapses` 判定で停止する。圧縮・接地の検査はそこまで通過する。`--liquefy-only` と `--reversal-only` は実行時と同じ1/120秒刻みで個別に通過する。

Debug構成のゲーム本体をビルドした後、次でD3D12診断シーンを実行できる。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Run-FluidSmoke.ps1
```

別のゲームプロセスが動いていれば中止する。診断用プロセスだけを起動し、通常材質とデバッグ表示を短時間描画して終了する。既存ログは退避・復元し、テストログを `tests/out/` に保存する。Debug構成ではD3D12のGPU-based validationが有効。Development構成でも `-Executable` で指定して初期化・計算・描画・正常終了を確認できる（GPU-based validationは有効でない）。Debug構成で確認したバッファ初期状態のWARNING ID 1328は残る。

実ゲームの水エミッターを含めて測るにはDevelopment構成をビルドし、次を実行する。500フレーム後に終了し、直近120フレームのFPS、粒子枠、CPU更新時間、GPUパス別時間を `tests/out/fluid-game-benchmark.txt` に保存する。実行前のログは退避・復元する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Run-FluidGameBenchmark.ps1
```

RTX 4060 Laptop GPUで約28,000粒子枠まで埋めた時、最終版の診断用ゲーム画面は直近120フレーム平均80.9 FPS（60 FPS未満1回）、エディターUIありは80.7 FPS（60 FPS未満0回）だった。ゲーム画面のGPU描画全体は12.29 ms、うち流体シミュレーション5.73 ms。これは静止したプレイヤーを含む診断シーンの実測であり、戦闘中の60 FPS保証ではない。プレイヤーの地形判定はCharacterMovementSystemが行い、PhysicsSystemの重複したGPUメッシュ判定を省く。ほかの剛体のGPUメッシュ判定はフレーム枠ごとの読み戻しを使い、GPU全体の待機を避けるため、接触結果は最大2フレーム遅れて反映される。非キャラクター剛体を追加した診断では約51 FPSで、GPUメッシュ衝突は依然として負荷が大きい。

## 残る制約・次の実機確認

- 3D密度場はプレイヤー付近の98.56×35.84×98.56単位に限定。外側は遠方LODで表示する。遠方にも連続した高品質な水面が必要なら、複数領域または疎グリッドが必要。
- 追加のGPUメモリはリソース寸法から約150 MiBと推算。旧経路用リソースも残る。GPUメモリの実測は別途必要。Developmentの診断シーン（RTX 4060 Laptop GPU、7,400粒子枠）では流体GPU合計18.38 ms、うち粒子シミュレーション12.62 ms、屈折・レイマーチ3.34 msだった。これはその診断シーンの一例で、実際のゲームプレイのフレーム時間ではない。
- 各材質の最前面と累積厚みで合成する近似。多層の屈折追跡、全反射、コースティクス、泡は未実装。飛沫はバルクの最前面深度で遮蔽する。
- 色は材質ごとの発生色を使う。水タイプ内に別々の色の液体を混在させるための色ボリュームは未実装。
- スライムの操作追従・分離・回収のコードは維持し、ばね加速度を密度から分離した。ただし、実ゲームの戦闘・液状化・回収を含む長時間プレイと、提示画像と同じカメラでの見た目の比較は未完了。
- 一様な試験粒子では連続面を確認できるが、実ゲームで粒子数・配置が不足する場所すべてを滑らかにする保証はない。法線表示と粒子デバッグを使い、物理配置と描画の問題を切り分ける。
- 薄膜補償は見た目を保つための近似。真のサブボクセル水厚や斜面の接触法線は再現していない。近傍探索範囲を広げた分のGPU負荷と、孤立飛沫への切替時のちらつきは実シーンで確認が必要。
