## 映像から確認できる特徴

| おおよその位置 | 観察 | 本ゲームで活かす方向 |
|---|---|---|
| 冒頭 | 頭部と連続した節による長い蛇状の形。小さな人型との対比で巨大さが分かる | 頭・胴・尾を読めるシルエットにする |
| 5〜10秒付近 | 高い位置の翼状部位、長い胴／首、空中の独立した塊が見える | 上空への経路を体の部位や分離部品で作る |
| 20秒付近 | 大きく広がった翼と、長く湾曲した部分が同時に見える | コアと周辺部位を別々に動かす |
| 23秒付近 | 多数の部品が空間へ散開した状態が見える | 散開を乗り継ぎ機会に転用する。ただし全片を対象化しない |
| 30秒付近 | 頭部と長い分節体がプレイヤー近くの画面を横切る | 接近の迫力と、近接遮蔽の両方を検証する |
| 40〜50秒付近 | 低い位置を通る分節体と、大きな輪を作る曲がりが見える | 体全体を使う攻撃予告と横方向の回避空間に利用する |

参考の強みは、形状の細密さに依存せず、全体の姿勢変化と部位ごとの追従で生物らしい大きさを見せること。
同一ボスのゲーム上の形態遷移条件や、映像内の全動作が自律AIであることまでは断定しない。

## 技術的な解釈

再現方法としては、胴体／頭部の移動を決め、首・尾を長さ制約付きの節で追従させ、翼には位相差と回転制限を与える構成が適する。
これは実装案であり、参考動画のソルバーを特定したものではない。

本ゲームでは次の順に評価する。

1. 戦闘状態が移動先・攻撃の予告／有効／回復時間を決める。
2. コア、翼根、首先などの制御点を更新する。
3. 節の姿勢を拘束・補間し、見た目を更新する。
4. 確定した姿勢から当たり判定とグラブ点を更新する。
5. その位置を対象選択・カメラ・HUDで共有する。

見た目だけを揺らして判定を旧位置に残さない。視覚的な揺れを理由に、攻撃範囲が予告後に無制限に変わる設計にもならないようにする。

## 提案：コアを持つ分節型の飛行ボス

参考の分節体と翼を取り入れ、地上と空中を移動する一体のボスを作る。
プレイヤーの狙いは「地上で予告を読む → 攻撃や体の部位を利用して上昇 → 空中のコアへ攻撃 → 継続か離脱を選ぶ」。
浮上中も攻撃機会を作り、着地待ちだけが正解になることを避ける。

### 役割を分ける

- **本体**: HP・状態遷移・全体の位置を管理する。
- **移動部位**: グラブ可能な体節や翼根。到達しても消滅せず、短い再選択待ちを設ける。
- **分離部品／破壊弾**: 攻撃と同時に上昇経路を作る。壊れた後も代わりの経路を確保する。
- **コア**: 有効打を入れる場所。乗り継ぎ部位と別の色・形で示す。
- **危険部位**: 予告された攻撃中にダメージを与える場所。グラブ可能な部位と混同しない。

すべての節をロック対象にせず、初期試作では選択可能な中継点を同時に3〜5個に絞る。

### 初期の戦闘ループ案

| 段階 | ボスの動作 | プレイヤーの選択 |
|---|---|---|
| 地上 | 首・胴を引いてから薙ぎ払う | 横へ回避／低い部位へグラブ |
| 離陸 | 翼を広げ、低い部位から順に浮上する | 離陸に合わせて乗り継ぐ／地上で立て直す |
| 空中攻撃 | チェーン可能な部品や弾を段階的に出す | 経路を登る／予告を見て途中離脱 |
| 空中の隙 | コアが露出し、移動速度と旋回を抑える | 空中カウンター／周辺部位で位置を整える |
| 被弾後 | 姿勢を崩すが、全中継点を消さない | 近くに残る／別部位へ移る／着地する |
| 着地 | 着地点を予告して降下し、回復時間へ入る | 着地点を避ける／移動しながらSTRAINを戻す |

これは参考動画で確認した戦闘仕様ではなく、本ゲームのために追加する仕様案。

## 到達可能性を先に設計する

- 現在の射程は約12〜24 units、質量100で18 units。初期の中継点間隔は8〜10 units程度から試す。
- 初期浮上高度は床から12〜18 units程度、上昇は2〜3回の乗り継ぎを目安とする。値は仮置き。
- 自機の大きさで通過できる経路を確保する。射程に入るだけでは成立としない。
- ボスの体・翼も経路の障害物になる。対象部位への接近を許す範囲と、他部位との衝突を分ける。
- 掴んだ部位の移動速度・加速度・旋回を制限し、追いつけない追尾を起こさない。
- コア露出時間は、離れた位置からの実測到達時間に判断・回避の余裕を足して決める。
- 途中失敗後も、低い中継点の再出現または固定アンカーで再挑戦できるようにする。
- プレイヤーは実時間、ボスはスロー時間で動く既存仕様を維持し、部位と攻撃予告も同じボス時間に従わせる。

## 現実装との対応

### 再利用できる部分

- `Game/Systems/ChronoSystem.cpp`: 射出・接近、移動対象の固定、回避優先、通過判定、カメラ補助、被弾理由。
- `Game/Chrono/ChronoComponents.h`: 対象種別、再利用アンカー、ボス状態の基礎。
- `Game/Chrono/ChronoRules.h`: 射程、接近速度、STRAIN、スロー。

### 拡張が必要な部分

- `Boss`は現在、phaseとclockを中心とした簡単な状態。地上／離陸／滞空／着地と、各攻撃の予告／実行／回復を明示する。
- 闘技場のボス移動は水平突進。高度制御、旋回、離着陸を追加する。
- 通常コースの上昇弾は固定座標列。移動するボスと床の間に、その都度成立する経路を作る。
- 弱点は本体中心へのoffsetを更新する方式。部位IDとローカル座標から、毎フレームの世界座標を求める方式へ拡張する。
- `Reachable`などのSweepは現在ステージのsolidsを使う。動くボス部位の連続衝突を追加する。
- 現在の接近には0.65秒の制限がある。移動部位に対しては相対運動も考慮した到達判定が必要。
- ボスカメラは単一中心を基準にする。大型の翼・長い胴・次の中継点も含めた画面内の広がりを評価する。
- `Engine/Model`に骨アニメーションの評価はあるが、検索範囲では専用の汎用IKソルバーを確認できなかった。初期試作は独立したプリミティブ部品で動きを検証し、必要に応じて骨へ適用する。

UnityのFinal IKをそのまま導入する案ではなく、現在のC++/DirectX構成に合わせて必要な節制御を実装する。

## 実装順序と合格条件

1. 仮形状で地上・離陸・滞空・着地をつなげる。攻撃なしでカメラとシルエットを確認する。
2. 動く部位を2〜3回乗り継ぎ、空中コアへ命中できるようにする。
3. 地上薙ぎ払いと空中攻撃を一つずつ加え、回避・中断・再挑戦を検証する。
4. 首・尾・翼の追従と分離／再集合の見た目を加える。
5. 小敵を混ぜ、STRAINと着地の判断を調整する。

合格条件:
- 自機が地上にいても、空中のボスへの経路を読める。
- 地上復帰を挟まず、空中で少なくとも一回有効打を入れられる。
- 接近中に回避へ移れて、攻撃予約が勝手に再開しない。
- 移動する部位に追いつけず、接近状態が延々続くことがない。
- 被弾した部位と理由が説明できる。
- 命中後に近くへ残る、部位を移る、着地する、の三択が成立する。
- 途中で弾や小敵を失っても、再挑戦経路が残る。

次に作るべき最小試作は「浮上する分節型ボスへ2〜3回チェーンし、空中のコアへ一撃を入れて任意方向へ回避する」一連の動作。
