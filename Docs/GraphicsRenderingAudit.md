# 描画改善と実機検証（2026-10-06）

通常ゲームのChronoFocusへ、HDRブルーム → GTAO → 地形・PBR → DLSS SR → 限定RT影の順で実装。UIはアップスケールとトーンマッピングの後、出力解像度で描画する。

| 項目 | 実装 | 制限 |
|---|---|---|
| HDRブルーム | シーン、屈折用背景、流体、3D PSOをFP16へ統一。6段縮小／5段拡大ピラミッド。初段だけで輝度抽出し、露出・トーンマッピング前に合成 | 内部HDR。HDR10ディスプレイ出力ではない。固定露出 |
| GTAO | 深度再構築、4スライス×左右6ステップのホライズン探索とコサイン積分、専用FP16ターゲット、深度による3×3 bilateral復元。流体深度も使用 | 時間方向の蓄積なし。画面外は対象外。前方描画の合成段で乗算するため、間接光だけを減衰する方式ではない |
| 地形 | 110×110グリッド。戦闘領域の周囲に緩やかな起伏と広がり | 戦闘領域は塗膜・流体・衝突面に合わせて平面を維持 |
| PBR材質 | 草地と3種類の岩にCC0 normal／roughness／AO。GGX／Smith／Schlick、非金属F0=0.04、AOは環境光へ適用。草カードは両面ライティング | 草のタイル感・形状・密度、環境光は改善余地あり |
| DLSS SR | NVIDIA Streamline 2.14.1の署名付きDLL。Quality、出力1920×1080、入力はSDKに問い合わせ（RTX 4060では1280×720）。HDRカラー、合成深度、カメラ・剛体・流体移流のモーション、32段Haltonジッター、自動露出、カット時の履歴リセット | 実験的統合。スキニング、逃げた泡の個別モーション、複雑な透明境界は近似。Frame Generation／Ray Reconstruction／Reflexは未導入 |
| 限定RT影 | 実デバイスのDXR 1.1／SM6.5対応を確認。地形と不透明な岩のBLAS、フレームごとのTLAS、半解像度inline RayQuery、深度付き遮蔽マスクとbilateral復元 | 太陽方向1レイの硬い影。既存シャドウマップへ控えめな乗算を追加する試作。直接光だけを置き換える完成版ではない。草・ボス・暗黙的な流体は遮蔽物へ登録しない |
| RT反射 | 地形・岩の最も近い交差点を追跡。実メッシュのUV、albedo／normal／roughnessと二次交差点の太陽の影を使用。半解像度、2本の光沢反射レイ。流体表面は深度から法線を近似し、地形・岩への交差分で既存環境反射を補正 | 映り込む実形状は地形・岩。草・敵・ボス・流体自体はまだTLASに含まれない。複数の透明層・透過レイは未対応。光沢のサンプリングは近似 |
| RT間接光 | 半解像度、8本のコサイン半球レイ。地形・岩の1回の拡散反射と空の照明。RT反射とともに専用の空間・時間フィルターで安定化し、HDRカラーへDLSS・ブルーム・DoFより前に合成 | 1バウンスのみ。流体の拡散GI、局所光源、複数バウンスは未対応。Ray Reconstructionではない |
| その他のポスト | 明部のレンズゴースト、16³ LUT、演出時の6タップブラーと8タップDoF。通常プレイの地面には両ぼかしをかけない | 光学フレア、物体別モーションブラー、物理的な近景ボケは未対応 |

## 設定

F7、またはポーズ画面のGRAPHICSから変更する。6種類の効果、露出、LOW／BALANCED／HIGH、DLSS Quality、RT影・RT反射・RT間接光の独立したON／OFFを提供。RTの3設定は即時反映。DLSSはレンダー解像度が変わるため次回ゲーム起動で反映。プリセットはDLSSとRTの選択を維持する。DLSSとRTの初期値はOFF。

設定は %LOCALAPPDATA%/LiquidTime/graphics-v1.txt に保存。旧7値の設定も読める。保存失敗は画面で通知。SDK／GPU／シェーダーを利用できない場合は利用不可と表示する。

## SDK・配布・再ビルド

NVIDIA RTX SDKライセンスはこの作業でユーザーが同意済み。全文はDocs/NVIDIA-RTX-SDK-LICENSE.txt。StreamlineヘッダーはMIT。DLLはGit管理に含めず、scripts/Setup-Streamline.ps1 -SdkArchive <Streamline-2.14.1.zip> で公式ZIPのハッシュと署名を検証して復元する。

実行時はEXE隣のStreamlineを優先し、開発時は作業ディレクトリのexternals/Streamline/binへフォールバックする。Release後処理と配布ZIPに署名済みDLLとライセンスを自動同梱する。DLLがなければ通常描画を使う。実行中にDLSS評価が失敗した場合は、その起動中の入力解像度を通常補間で表示し、状態を利用不可へ変更する。

RTシェーダーのソースとResources/shaders/RtShadow.cso、RtLighting.csoを同梱。DXCはゲーム実行時には不要。変更時はscripts/Build-RtShadow.ps1 -Dxc <dxc.exe>で両方のSM6.5シェーダーを再生成する。確認済みコンパイラはMicrosoft DXC v1.9.2609（2026-09-29）。公式ZIPのSHA256：AD31B1FC8443175D204F77A611FDB3EF2EC42759BDC2F1167368DE24A4A7E7F1。

PBR画像の出典とCC0ライセンスはResources/Credits/PBR-Materials.md。マニフェストで各画像、クレジット、RT CSOを検査する。

## 次の改善

RT影を直接光のライティング段へ移し、重複合成を解消する。太陽の面積に基づく複数レイと時間方向デノイズを加える。DLSSの透明境界とスキニング入力を改善し、Nativeと動画像で比較する。RT反射の対象を動的な敵・ボスへ拡張する。流体自体の反射／透明交差には専用の表面表現と履歴設計が必要。

公式資料：[GTAO論文](https://www.activision.com/cdn/research/Practical_Real_Time_Strategies_for_Accurate_Indirect_Occlusion_NEW%20VERSION_COLOR.pdf)、[DLSS統合ガイド](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS.md)、[手動フック](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideManualHooking.md)、[DXR仕様](https://microsoft.github.io/DirectX-Specs/d3d/Raytracing.html)、[DXCリリース](https://github.com/microsoft/DirectXShaderCompiler/releases/tag/v1.9.2609)。

## 地面のちらつき・設定画面の修正

地面の微細な白い輝点は、1段しかないテクスチャと高周波の法線による鏡面反射のエイリアシングが主因。LoadTexture2Dで全ミップチェーンを生成・転送し、sRGBカラーと線形データを区別してキャッシュする。1×1テクスチャはそのまま扱う。3Dサンプラーに8倍異方性フィルタを設定。乾いた草地の粗さの下限を0.78とし、法線の画素内変動から鏡面ローブを広げる。

ゲームUIは固定の1920×1080最終テクスチャに描画されるが、Canvasがエディタ内Gameパネルのサイズで縮小していたため二重縮小が起きていた。出力テクスチャを基準に統一した。EditorUIが既に内部解像度へ変換したマウス座標と描画位置を一致させ、ヒット判定も修正した。

設定画面右上にNVIDIA DLSS Super Resolution専用パネルとON / QUALITY・OFFの独立ボタンを配置。再起動での反映と現在適用中の状態を表示する。RT影も独立したON／OFFボタンへ変更。

検証：tests/Run-UISmoke.ps1 -Graphicsは、Gameパネルの複数サイズでDLSSボタンのヒット判定、実際のUpdateGraphicsのON→OFF操作、草地カラー・法線・粗さの11段ミップ、GPU画面キャプチャを確認。画像はtests/out/graphics-ground.pngとgraphics-settings.png。ポスト効果9項目の描画テストも通過。
追加検証：-Rogue -DLSS -RT -Validationも通過。DLSS評価／RT影321フレーム、遮蔽9780画素／非遮蔽258635画素。D3D12検証レイヤーのERROR／CORRUPTIONなし。


## DLSS適用時の影の縞模様の修正

GTAOはDLSS入力の1280×720深度を読み、1920×1080の出力画素のUVと隣接幅で位置・法線を再構成していた。複数の出力画素が同じ深度を異なる位置として扱い、滑らかな傾斜面にも偽の自己遮蔽が発生した。DLSSライブラリを使わないWARP描画でも、入力／出力比2:3の平面テストで可視率0.735～1.000となり、問題を再現した。

GTAOターゲットとビューポートを入力深度の解像度へ統一。全サンプルを実際の深度画素中心で再構成し、スライス方向の二重投影補正を修正。画素丸めでスライスから外れたサンプルを投影し、同一平面・表面より下のサンプルを遮蔽候補から除外する。無遮蔽時の積分値で正規化し、視線・法線による平面の明るさの変化を抑える。

RT影でも縮小したマスクのUVではなく、読み取った入力深度画素のUVで逆投影するよう修正。RtShadow.csoを再生成。GTAO／RT合成は各マスクの実解像度で深度付きサンプルを読み、異なる表面の深度を線形補間しない。深度に一致するサンプルがない場合は可視扱いとし、輪郭に黒い線が出る問題を修正した。

回帰検証：tests/Run-FluidTests.ps1 -Case '--graphics-only'。傾斜3種類×出力倍率1.0／1.5／0.5の9条件で、平面の可視率は1.000～1.000。接地の可視率0.540で必要な陰影は維持。深度が異なるGTAO／RTマスクの拒否テストは追加の暗化なし（差分0.000）。既存のポスト効果9項目も通過。

実機比較：tests/Run-UISmoke.ps1 -Shadowsはゲームとカメラを固定し、追加の陰影なし／GTAOのみ／RT影のみ／両方の画面をtests/out/shadow-*.pngへ保存する。DLSS評価とRT影の実行数、およびRTマスクに遮蔽・非遮蔽の両方があることも検証する。診断シーンは設定を保存しない。

最終実機結果（RTX 4060 Laptop）：DLSS評価125フレーム／RT影61フレーム。遮蔽17616画素／非遮蔽341098画素。4枚の比較画像で地面の横縞とGTAO由来の輪郭の黒線が消えたことを確認。D3D12検証のERROR／CORRUPTIONなし（既存のID 1328警告は残る）。Development x64ビルド、リソース251ファイルのCheckOnly、git diff --checkも通過。修正の反映にはアプリを再起動する。


## カメラの向きで変形する流体の影（2026-10-08）

GPUFluidShadowVSはgViewからゲームカメラの右・上方向を取り、粒子の影用ビルボードをカメラ向きに作っていた。一方、頂点の投影にはライトのgViewProjを使っていた。同じ粒子と光源でもカメラ回転によって影の投影面積と形状が変わり、地面上の不要な影の変化につながる。

影用ビルボードは直交投影のライトVPの列から右・上方向を取得し、投影スケールを正規化するよう修正した。ゲームカメラへの依存を除いた。画面表示用の粒子の向きは変更していない。

tests/GraphicsPostValidation.inlに、実際のGPUFluidShadowVSをWARPで描画する回帰テストを追加。粒子と光源・ライトVPを固定し、カメラのヨー・ピッチのみ5方向に変更する。修正前は最初の影との比較で合計1414画素が変化してテスト失敗。修正後は影が772画素を覆い、変化は0画素で通過。影を消してテストを通すことがないよう、描画面積も検証している。既存のGTAO傾斜面9条件とポスト効果・深度拒否のテストも通過。

実機検証：Development x64ビルドとtests/Run-UISmoke.ps1 -Shadowsが通過。DLSS125フレーム／RT影61フレーム、遮蔽11755画素／非遮蔽346981画素。D3D12 ERROR／CORRUPTIONなし。比較キャプチャを確認し、リソースCheckOnlyとgit diff --checkも通過。アプリ再起動で修正したシェーダーを読み込む。


## 斜め視点の横方向の影への追加修正（2026-10-08）

前回の流体ビルボード修正だけでは、草の板と透明エフェクト、影の有限範囲の処理は解決していなかった。通常・インスタンスの影パスに共通のShadowCaster判定を設け、透明な攻撃・発光エフェクトや深度を書かない水滴等を不透明な影から除外する。MeadowGrassは専用VegetationShadowの深度パスで実際のアルベドアルファを0.42で切り抜く。表示側のUVとしきい値に一致させ、材質ごとの自動テクスチャ差し替えもこのパスでは抑止して描画側と同じ草のアトラスを使う。

有限100×100のシャドウ範囲では、範囲外を即座に可視にする処理が地面に直線の境目を作り得た。ShadowFrustum.hlsliで範囲の外周8%を可視へ滑らかにつなぎ、PBR／Default／InstancedObj／EnhancedTerrainのサンプリングへ適用した。D32のDepthBias=100000は深度0.5付近で約0.6ワールド単位の大きなずれを作っていたため、1500に縮小した。斜め方向の通常の投影影そのものを削除する変更ではない。

WARP検証：実際のVegetationShadowPSでアルファ0／0.41は深度を書かず、0.43／1は書くことを確認。透明エフェクトの除外と通常の物体の保持を確認。影範囲の外周が連続して明るくなり、中央の影強度が維持されることを描画テストで確認。既存の5方向カメラ回転・GTAO傾斜9条件・ポスト効果／深度拒否も通過。

実機：tests/Run-UISmoke.ps1 -Shadows -Obliqueで低い斜め視点から4種の影の組み合わせを比較。DLSS125フレーム／RT影61フレーム、遮蔽20817画素／非遮蔽326826画素。D3D12 ERROR／CORRUPTIONなし。Development x64ビルド、リソース253ファイルのCheckOnly、git diff --check通過。修正前の斜め視点はtests/out/shadow-oblique-before.png、最終のGTAO＋RTはshadow-oblique-after.png。スクリーンショットと完全に同一のプレイ状態を再現したものではなく、診断シーンの低い斜め視点での確認である。

## Release版でDLSSを利用できない問題（2026-10-08）

Releaseの後処理と配布ZIPはResourcesだけを同梱しており、開発時に参照するexternals/Streamline/binのDLLが実行ファイルのフォルダーには存在しなかった。DLL検索も作業ディレクトリに依存していたため、Releaseのフォルダーから起動するとDLSS初期化が失敗した。

Package-Streamline.ps1を追加し、NVIDIA署名を確認した4つのDLLとライセンス文書をReleaseと配布ZIPのStreamlineフォルダーへコピーする。ランタイムは実行ファイル隣のStreamlineを優先し、開発時のみ従来のSDK配置へフォールバックする。デバイス初期化結果をログへ追加し、設定画面にもDLL未配置・署名確認・GPU対応等の具体的な失敗理由を表示する。

Release x64ビルド成功。tests/Run-DlssPackageSmoke.ps1で実行ファイルのフォルダーから起動し、DLSS評価119フレーム、DLSS SR available、D3D12 ERROR／CORRUPTIONなしを確認。tests/out/dlss-release-settings.pngでは「現在適用中：QUALITY」を確認した。New-SlimeRelease.ps1で配布ZIPを再生成し、4つのDLLと2つのライセンス文書をZIP内で検証した。

## RT反射・間接光の導入（2026-10-08）

地形・岩の既存BLAS／TLASを共有し、InstanceIDとPrimitiveIndexから実メッシュの位置・法線・UV、描画時の色、PBRテクスチャへアクセスする。三角形属性はフレームスロットごとのGPUメモリへキャッシュし、モデル／LODの追加時のみ更新する。反射は2レイ、拡散間接光は8レイ。交差した面の直接太陽光には追加の遮蔽レイを使用する。空は既存の環境マップを使用する。スライムの流体表面は合成深度から受け手の位置・法線を近似するが、反射先の流体形状はまだ登録しない。

半解像度の結果は5×5の空間・深度フィルターと流体／不透明面の区別で復元する。遠景の傾斜面では単純な同一深度判定が交互の行を拒否して横縞になるため、近傍の逆深度の勾配から各サンプル位置の平面深度を予測する。HDR合成の後にDLSSを評価し、ブルーム・DoF・トーンマッピングへ渡す。専用のRT時間方向蓄積やDLSS Ray Reconstructionは追加していない。

設定にRT反射／RT間接光の独立ON／OFFを追加。保存項目を既存形式の末尾へ追加し、古い設定を維持する。プリセット変更はDLSSと3つのRT設定を保持する。RT影OFFでも反射・間接光を実行でき、その場合は不要な影マスクのディスパッチを省略する。初期値は両方OFF。

WARP：既存の影・GTAO・HDR検証に加え、RT反射／間接光の可視な合成、別深度と別表面種別の拒否、実HDR合成シェーダーによる急傾斜の透視平面を検証。平面の出力は0.1800～0.1800で横縞なし。Release x64ビルド成功。

実機の最終結果（RTX 4060 Laptop、tests/Run-RtLightingSmoke.ps1）：DLSS ONはRT照明145フレーム／DLSS471フレーム、反射349031画素・実形状への交差126203件、間接光346196画素・交差237570件。NativeはRT照明145フレーム／DLSS0フレーム、反射348096画素・交差124913件、間接光345899画素・交差237028件。各効果の独立ON／OFF、影OFFでの照明、実UIクリック、HIGHでもRT設定が維持されることを確認。両方ともD3D12 ERROR／CORRUPTIONなし（既存ID1328警告は残る）。FPSの比較測定は含まない。

tests/out/rt-lighting-{dlss,native}-{off,reflections,indirect,combined,oblique,settings}.pngに比較画像を保存。通常戦闘を5秒ウォームアップ後に固定し、カメラはプレイヤー位置から相対配置する。泡の装飾は凍結中も動くため完全な画素単位差分ではない。リソース256ファイルと新しいRTシェーダーをReleaseとdist/SlimeAssault-Release.zipへ同梱した。

## 移動時のぼやけ・RTちらつき・景観モデルの更新（2026-10-08）

通常のPresentationでもDoF強度0.75を設定し、カメラモーションブラーも常時有効だった。通常プレイのDoF強度を0とし、明示的なcinematicCameraフラグがある開始・ボス・強化選択の演出だけでモーションブラーを有効にする。設定UIのラベルも「演出時モーションブラー」に変更。既存設定は維持する。

RTのサンプル方向を0.5単位の世界グリッドで乱数回転し、カメラ距離でTLASのモデルも変えていた。安定した半球列と固定形状を使用する。RT反射・GIが有効なときは受け手のラスタ形状も一致させる。小石はスキャンモデルの固定縮小形状を使用し、距離で切り替えない。

RtLightingDenoise.hlslを追加。RTの光だけに逆深度平面を使う5×5空間フィルターをかけ、静的な面では前フレームへ再投影して履歴を蓄積する。深度不一致と表面種別の切り替えを拒否し、近傍範囲へ履歴をクランプする。設定変更・カット・RT停止で履歴を無効化する。動く流体は空間処理のみで残像を避ける。地面のアルベドや通常描画にはこのフィルターをかけない。DLSS Ray Reconstructionの実装ではない。

FBXインポートはPoly HavenのノードにあるZ-up軸変換・単位・配置を反映し、UVのVをDirectXに合わせる。Boulder 01はLOD0～3の全てが可視として出力されていたため、LOD0だけを読み込み、重複面による描画・レイ交差を解消。実モデルのLOD0三角形数66122を検証する。草の面を固体用LODへ変換せず、公式16-bitアルファは正規化して8-bit RGBAへ格納する。両面の空の光と透過光を補い、黒い針金状の見え方を抑える。

新規導入：Poly HavenのBoulder 01、Namaqualand Boulder 02、Grass Medium 02、Leafy Grass（4Kカラー／2Kデータ）。公式CC0の商用利用・改変・再配布条件を確認し、配布元MD5とSHA-256を記録。岩壁の極端な巨大化を解消し、遠景の岩群・手前の小石・草束を地形に接地させる。出典はResources/Credits/MeadowRefresh.mdとMeadowRefreshSources.json。画像を含む280リソース、約154.17 MBをReleaseへ同梱する。敵・ボスのモデルやゲームの衝突／塗膜面はこの変更では置き換えない。

検証：WARPで実デノイザーのノイズ除去、深度による履歴拒否、照明変化のクランプ、流体の残像防止、カメラ移動時の再投影を確認。既存の影、GTAO傾斜平面、HDR、RT合成とCPUゲームルール／カメラの回帰検証も通過。実機検証は開始演出が完了して通常プレイのDoF強度0となったことを確認してから固定し、RTの独立切替、移動カメラ、手前の新素材をキャプチャする。移動時の床の画素差はUIと流体を避けた領域で測る大きな点滅の検出であり、画素完全一致や長時間プレイの画質保証ではない。

最終Release実機結果：NativeはRT照明234フレーム、反射334520画素／形状交差36395件、間接光331981画素／交差26312件、床の移動差0.0427731。DLSS QUALITYはRT照明234フレーム／DLSS505フレーム、反射334498画素／形状交差37105件、間接光332108画素／交差26315件、床の移動差0.0164513（閾値0.18）。両方ともD3D12 ERROR／CORRUPTIONなし。DLSSテストの最初の150秒制限では移動キャプチャ途中で終了したため、モデル読み込みと開始演出を待つ制限を240秒に延長し、完走を確認した。通常プレイ移行の条件は維持する。

dist/SlimeAssault-Release.zipを最終ビルドから再生成。公式20ファイルのSHA-256、3つの新FBX、4K地面、新デノイザー、出典、4つのDLSS DLL、ZIP CRCを検証済み。キャプチャはtests/out/rt-lighting-{native,dlss}-scenery.pngとmoving-*.png。git diff --check通過。

## ゲームシーンの描画負荷の改善（2026-10-09）

実機のGPU時刻を取得し、同一実行ファイルの診断専用 `--scenery-baseline` で景観の最適化前後を比較した。草束は1束7942三角形あり、約570束と岩・小石を画面外まで描画していた。RT反射／間接光ではラスタ形状をRTと合わせるため岩の詳細形状も固定使用していた。加えて、静的モデルの頂点・インデックスはUPLOADヒープにあり、GPUが毎フレームCPU側メモリから読み出していた。RTレイ自体より、景観と影の形状描画が主な負荷だった。

草は接続された葉を丸ごと残す専用LODへ変更し、UV・法線を維持して22／60単位で切り替える。小石は固定の軽量形状を共有する。景観はワールド変換した8隅の境界箱でカメラ視野から保守的に除外する。影パスは別にライトの視野で判定するため、画面外の物体が落とす影は維持する。RTの登録にはカメラでの除外を適用せず、岩はカメラに依存しないLOD1を使い、反射／間接光のラスタ形状も一致させる。

静的景観とそのLODを初期化時にGPU専用のDEFAULTヒープへ転送し、キュー完了後に一時転送バッファを解放する。フレーム中に転送・待機は追加しない。動的頂点やスキニングの経路は維持する。TLASは各フレームスロットのインスタンス形状・変換が変わったときだけ再構築し、カメラ回転では再利用する。RT照明は元の半解像度960×540、反射2レイ／間接光8レイを維持する。

RTX 4060 Laptop、1920×1080、Release、開始演出完了後、同一カメラで各条件40フレームを平均した結果。画面キャプチャと検証レイヤーはFPS測定中には実行しない。

| 条件 | 修正前 | 修正後 |
| --- | ---: | ---: |
| DLSS OFF・RT OFF | 10.08 FPS／99.19 ms | 85.92 FPS／11.64 ms |
| DLSS OFF・RT影／反射／間接光 ON | 5.36 FPS／186.68 ms | 74.11 FPS／13.49 ms |

通常更新を再開したRT全有効の追加条件では74.56 FPS、ゲームロジックのCPU時間は0.22 ms。DLSS QUALITYでは同じ追加条件が52.64 FPSだった。今回の測定ではDLSSの処理費用が上回り、Nativeの方が速かった。戦闘の全局面や長時間プレイのFPS保証ではない。RT OFFのカメラ内描画は約1105万から215万三角形、影描画は約1105万から76万三角形へ減少。静的なRT条件でTLAS再構築は各スロットの初回のみ（合計2回）。

測定スクリプトは `tests/Run-SceneryBenchmark.ps1`。結果は `tests/out/scenery-before.txt`、`scenery-final-native.txt`、`scenery-final-dlss.txt`。診断条件は永続設定を変更しない。CPU回帰検証で葉の単位を保ったLOD、ゲームルール、カメラ演出が通過した。

Release／Development x64ビルド成功。実機RT検証はNative／DLSSとも照明234フレームで通過し、DLSS評価576フレームを確認。カメラ回転前後のTLAS構築数は2回のままで、実際に岩を移動した後には再構築された。床の移動差はNative 0.04628、DLSS 0.02844（閾値0.18）。RTの独立切替と設定UI操作も通過し、D3D12 ERROR／CORRUPTIONなし（既存ID1328警告は残る）。最終配布ZIPは更新したRelease実行ファイル、280リソース、署名確認済みのDLSS DLLを同梱する。
